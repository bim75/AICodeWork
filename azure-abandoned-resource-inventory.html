READ-ONLY CLEANUP REPORT

Azure Abandoned Resource Inventory

Inventory Azure subscriptions and flag likely abandoned or orphaned resources. This tool is evidence-only: it does not delete, stop, resize, or modify anything.

Start in Azure Cloud Shell

  1. Open Azure Portal.
  2. Open Cloud Shell from the top toolbar.
  3. Choose Bash.
  4. Paste the commands below.
curl -L -o azure-abandoned-inventory.sh https://raw.githubusercontent.com/bim75/AICodeWork/main/azure-abandoned-inventory.sh
chmod +x azure-abandoned-inventory.sh
./azure-abandoned-inventory.sh

The script polls your visible Azure subscriptions, then gives you a menu.

Subscription menu

You can choose:

  • 0 — all enabled subscriptions
  • 1 — one subscription by number
  • 1,3,4 — multiple subscriptions by number
  • r — refresh/poll subscriptions again
  • q — quit

After you choose, it shows the selected subscription(s). Press Enter to run, or type b to back up, r to refresh, or q to quit.

After each run, it returns to the subscription menu so you can run another subscription or run all.

What it flags

Unattached disks

Managed disks with no current owner/attachment.

Unattached NICs

Network interfaces not attached to a VM/private endpoint.

Unassociated public IPs

Public IPs not associated to a frontend or NIC.

Old snapshots

Snapshots older than the configured threshold, default 90 days.

Stopped/deallocated VMs

VMs that Resource Graph exposes as stopped/deallocated.

Missing tags

Resources missing owner/environment tags.

Output files

Each script session creates a timestamped directory under azure-abandoned-inventory-output/. Each selection gets its own run folder.

Optional settings

# Change old snapshot threshold from default 90 days
DAYS_OLD=180 ./azure-abandoned-inventory.sh

# Change output directory
OUT_DIR=./my-azure-report ./azure-abandoned-inventory.sh

Safety review process

  1. Open cleanup-candidates.csv.
  2. Sort by severity and reason.
  3. Fix missing owner/environment/cost-center tags first.
  4. Tag obvious orphaned objects before deletion, e.g. cleanup-candidate=true.
  5. Wait 7–30 days if there is uncertainty.
  6. Delete only after owner confirmation and backup/snapshot/export where appropriate.

Important: “unused” is not always directly knowable from Azure inventory alone. Key Vaults, private DNS zones, route tables, managed identities, backup vaults, and Log Analytics workspaces can be dependencies even when they look quiet.
